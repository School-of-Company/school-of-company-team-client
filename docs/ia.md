# 정보 구조 (IA)

이후 단계가 추가할 화면의 자리와 내비 순서를 정합니다. **코드에는 빈 메뉴·준비 중 화면을 만들지 않습니다.** 각 단계의 프론트 워커가 자기 화면을 실제 API와 함께 완성할 때 이 문서의 자리에 넣고, 사이드바(`widgets/app-shell`)는 한 번에 한 워커만 고칩니다(계획 3.4).

## 프로젝트 안

프로젝트 화면은 제목 아래 탭(`ProjectNav`)으로 나눕니다. 탭 순서는 고정합니다.

| 탭         | 경로                                                          | 단계 | 내용                                                                                                                        |
| ---------- | ------------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------- |
| 보드       | `/projects/{id}`                                              | 지금 | 칸반. 3단계에서 그룹 축에 버킷·리뷰어, 스윔레인 추가(새 탭 아님)                                                            |
| Sprint     | `/projects/{id}/sprints`, `/projects/{id}/sprints/{sprintId}` | 4    | 목록 → 상세(계획 · 진행 · 리뷰 · 회고를 상세 안의 탭으로, `?tab=`). 진행 방식이 Kanban 인 프로젝트에는 탭을 두지 않는다     |
| Milestone  | `/projects/{id}/milestones`                                   | 4    | 목록과 진행 막대. 상세 경로 없이 목록 위 패널(Dialog)로 연다                                                                |
| 달력       | `/projects/{id}/calendar`                                     | 11   | 그 프로젝트의 일정·업무 마감·마일스톤·스프린트. 일정은 대화상자로 만들고 고친다                                             |
| 링크       | `/projects/{id}/links`                                        | ②    | 자주 여는 링크 카드 그리드. 추가·수정·정렬은 참여자·PM·헤드 어드민, 삭제는 만든 사람·PM·헤드 어드민. 미리보기는 Dialog      |
| 화이트보드 | `/projects/{id}/whiteboards`, 편집은 `/whiteboards/{id}`      | 10   | 프로젝트 보드 목록. 편집 화면은 팀 공용과 같은 경로(서버 `docs/spec/s10-whiteboard.md`)                                     |
| 설정       | `/projects/{id}/settings?tab=`                                | 지금 | 기본 정보 · 멤버·권한 · 연동, 이후 `알림`(2단계, 토글 3개) · `계획 버킷`(3단계) · `자동화`(8단계) 탭 추가. PM·헤드 어드민만 |

- 설정 기본 정보에 단계(검토·준비·개발·검증·운영·종료·보류)·유형(외주·내부·R&D)·진행 방식(Sprint·Kanban)이 있다. 프로젝트 목록은 단계·유형 배지와 단계 필터를 보여 준다.
- 현재 Sprint 보드는 별도 화면이 아니라 보드 탭의 필터(`?sprint=current`)입니다.
- 이월(Carry Over)·종료는 Sprint 상세의 대화상자이며 경로를 만들지 않습니다.

## 규칙

- 한 항목은 한 단계의 화면이 실제 API와 함께 완성될 때 들어갑니다. "준비 중" 메뉴, 비활성 링크, 빈 페이지는 만들지 않습니다.
- 상태(필터·탭·선택)는 URL에 둡니다(`?tab=`, `?task=`, `?q=`).
- 개인 업무는 어떤 집계·목록·검색에도 본인 외에는 나오지 않고, 비공개 원본 업무는 프로젝트 권한과 현재 GitHub 권한을 모두 가진 사람에게만 나옵니다.
- 라벨은 짧은 한국어 명사입니다(design.md). 영어 이름은 고유 개념(Sprint, Milestone, Runbook)에만 씁니다.

## 팀 문화

`/culture` 한 화면을 탭(`?tab=`)으로 나눕니다. 탭마다 서버 섹션 문서 하나(`/api/v1/team-guide/{section}`)이고, 보기·고치기(헤드 어드민)·수정 이력이 탭별로 따로 있습니다.

| 탭            | `?tab=`         | 섹션            |
| ------------- | --------------- | --------------- |
| 팀 문화       | `culture`(기본) | `CULTURE`       |
| 협업          | `collaboration` | `COLLABORATION` |
| 프로젝트 진행 | `project`       | `PROJECT`       |
| 개발          | `development`   | `DEVELOPMENT`   |
| 운영          | `operations`    | `OPERATIONS`    |
